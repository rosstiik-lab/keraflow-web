# KERAFLOW — правила роботи для Claude Code

## Проєкт
Один файл www/index.html — застосунок KERAFLOW для плиточників (облік об'єктів, робіт, матеріалів, оплат, замовників, працівників). Без збірки, чистий HTML/CSS/JS, дані в localStorage (ключ keraflow-data). Папка www/ — webDir для Capacitor (обгортка під iOS/Android), деплой на Vercel теж читає саме з неї.

## Git — ОБОВ'ЯЗКОВО
- Завжди працюй і комітуй безпосередньо в гілку main.
- НІКОЛИ не створюй окремих гілок (claude/..., feature/... тощо).
- Перед початком роботи переконайся, що знаходишся на main і вона синхронізована з origin/main.
- Після кожної завершеної зміни — коміт з описовим повідомленням і одразу push у main.

## Тести
- Не запускай регресійні тести, Playwright чи інші автоматизовані перевірки, якщо про це прямо не попросили.
- Перевірка результату відбувається вручну на production-сайті після деплою.

## Стиль (design tokens) — не змінювати без прямого запиту
- Фон: #0A0D14
- Панелі: #11151F / #161B26
- Межі: #232838
- Акцент (бурштиновий): #F5B93D
- Текст: #F2F3F6, приглушений: #8B93A3
- Зелений (успіх/виконано): #3DD68C
- Червоний (борг/помилка): #E5534B
- Шрифти: Manrope (текст), IBM Plex Mono (числа/суми)
- Іконки: лінійні SVG (stroke, без заливки, без emoji)
- Навігація: сайдбар зліва на широких екранах (≥860px), нижня панель на вузьких — обидва варіанти з однаковим набором пунктів
- Модальні вікна НЕ закриваються кліком поза межами — лише кнопками

## Загальні принципи UX
- Видалення пов'язаних сутностей (замовників, позицій прайсу, категорій, одиниць виміру), які використовуються деінде, має бути заблоковане з поясненням, а не дозволене.
- Підтвердження перед видаленням критичних даних (об'єкт, робота, аванс, кімната).
- Дані завжди прив'язані до конкретного об'єкта/замовника/працівника — ніколи не зберігаються "глобально", якщо мають належати комусь конкретному.

## Формат відповіді
Після виконання завдання коротко підсумуй, що саме змінено, і підтверди, що зміни запушені в main.
